    Input¶

    The Input module provides a strongly-typed, action-based abstraction over Unity new input system that works the same way on Xbox, PlayStation, and Nintendo Switch. You describe what the player wants to do (Jump, Move, Apply) and the SDK maps it to the appropriate device button or axis at runtime.

    Features¶

    • Action-based input - bind, read by name or reference
    • Strongly-typed actions - bool, float, Vector2
    • Binding builder - chain BindAs… → To… → WithProcessor… → Complete()
    • Pre-made action set (BaseInputActionSet) for common usage
    • Custom action sets - group your game-specific actions
    • Cross-platform action mapping - Apply / Cancel resolve to the right face button per platform
    • Pluggable processors - deadzone, invert, repeat-delay, or your own IProcessor<T>
    • Controller glyph support - per-platform icon sets
    • Provider abstraction - the runtime decouples your code from Unity new Input System
    • Event-based or polled - subscribe to Performed, or call .Read()

    Setup¶

    Input System is automatically initialized by the RuntimeBootstrap component during application startup. It is also automatically deinitialized when the OnDestroy lifecycle event is triggered, allowing the system to correctly release resources and unregister callbacks.

    Warning

    You must have an UpscaleSDKConfig asset at Resources/UpscaleSDK/Config with glyph sets assigned for every platform you plan to ship on. Without it, TryGetGlyph() returns null and gamepad detection on Desktop platform falls back to GamepadType.None.

    Quick start¶

    Read input (polling)¶

    bool jumpHeld   = BaseInputActionSet.Instance.South.Hold.Read();
Vector2 move    = BaseInputActionSet.Instance.LeftStick.Read();
float trigger   = BaseInputActionSet.Instance.RightTrigger.Read();

    Subscribe to input events¶

    private void OnEnable()
{
    BaseInputActionSet.Instance.Apply.Press.Performed += OnApply;
}

private void OnDisable()
{
    BaseInputActionSet.Instance.Apply.Press.Performed -= OnApply;
}

private void OnApply(bool pressed)
{
    Debug.Log($"Apply pressed: {pressed}");
}

    Always unsubscribe in OnDisable / OnDestroy - InputAction<T> events are long-lived and will keep your objects alive otherwise.

    Core concepts¶

    Action, Action Group, Action Set, Action Definition¶

    Term What it is
    InputAction<T> A single named input that produces a value of type T and fires Performed
    ButtonActionGroup A button bundled (based on InputAction<T>) into its three trigger variants: Press, Hold, Release
    InputActionsSet<T> A collection of actions you activate/deactivate as a single unit
    InputActionDefinition<T> A ScriptableObject asset that authors an action in the Inspector

    Button triggers¶

    Every button can exposed as three actions via ButtonActionGroup:

    Trigger Fires
    Press Once on the frame the button goes down
    Hold Every frame while the button is held
    Release Once on the frame the button goes up 
    BaseInputActionSet.Instance.South.Press.Performed   += OnJumpStart;
BaseInputActionSet.Instance.South.Hold.Performed    += OnJumpCharging;
BaseInputActionSet.Instance.South.Release.Performed += OnJumpRelease;

    Cross-platform action mapping¶

    Some semantic actions (Apply, Cancel, …) automatically resolve to the right physical button on each platform. Use these instead of hard-coding South / East when you want platform-appropriate button mappings.

    Action PS 4 PS 5 Switch Xbox
    Apply X / O X A A
    Cancel O / X O B B
    Base Square Square X Y
    Extra Triangle Triangle Y X 
    BaseInputActionSet.Instance.Apply.Press.Performed  += OnConfirm;
BaseInputActionSet.Instance.Cancel.Press.Performed += OnBack;

    BaseInputActionSet¶

    BaseInputActionSet is the pre-made set covering every standard gamepad input. It is created lazily on first access to .Instance.

    Category Members
    Face buttons (raw) South, West, North, East
    Face buttons (mapped) Apply, Cancel, Base, Extra
    System buttons Start, Select
    Shoulders / stick clicks LeftShoulder, RightShoulder, LeftStickButton, RightStickButton
    D-pad buttons DpadUp, DpadDown, DpadLeft, DpadRight
    Triggers (float) LeftTrigger, RightTrigger
    Stick axes (float) LeftStickX, LeftStickY, RightStickX, RightStickY
    Sticks / D-pad (Vector2) LeftStick, RightStick, DPad

    All button members are ButtonActionGroup (.Press / .Hold / .Release). Float and Vector2 members are InputAction<float> / InputAction<Vector2>.

    Custom action sets¶

    For game-specific input, subclass InputActionsSet<T> and define your bindings in Initialize:

    public sealed class PlayerInputActionSet : InputActionsSet<PlayerInputActionSet>
{
    public InputAction<bool>    Interact { get; private set; }
    public InputAction<Vector2> Move     { get; private set; }
    public InputAction<float>   Aim      { get; private set; }

    protected override void Initialize(InputSetBuilder builder)
    {
        Interact = builder.BindAsBool("Interact")
                          .ToAction(GamepadAction.Apply, ButtonTrigger.Press)
                          .Complete();

        Move     = builder.BindAsVector2("Move")
                          .ToLeftStick()
                          .WithDeadzone(0.15f)
                          .Complete();

        Aim      = builder.BindAsFloat("Aim")
                          .ToRightTrigger()
                          .Complete();
    }
}

    Access through the singleton:

    PlayerInputActionSet.Instance.Move.Performed += OnMove;

    Lifecycle¶

    // Enable/disable callbacks for the entire set
PlayerInputActionSet.Instance.Activate();
PlayerInputActionSet.Instance.Deactivate();

bool isActive = PlayerInputActionSet.Instance.IsActive;

// Release all bindings registered by this set
PlayerInputActionSet.Instance.Dispose();

    Deactivate() is the right tool for "pause player input while a menu is open." Dispose() is the right tool for scene unload or shutdown.

    Action Definitions¶

    InputActionDefinition is the asset-based counterpart to the fluent builder. Each definition is a ScriptableObject that holds a list of input sources and a list of processors; at runtime, calling .Build() returns a wired-up InputAction<T>. Use them when you want input to be authored in the Inspector - by designers, modders, or just so the binding lives next to the prefab that consumes it - instead of expressed in code.

    Definition asset Value type Returns
    BoolActionDefinition bool InputAction<bool>
    FloatActionDefinition float InputAction<float>
    Vector2ActionDefinition Vector2 InputAction<Vector2>

    Creating a definition¶

    Project window → right-click → Create → Upscale SDK → Input → Actions → <Bool / Float / Vector2> Action

    Configuring it¶

    In the inspector you fill two reorderable lists:

    • Sources - one or more IInputSource<T> instances (e.g. a gamepad button source, a stick axis source). The dropdown is auto-populated with every concrete IInputSource<T> matching the asset's value type.
    • Processors - one or more IProcessor<T> instances applied in order. The custom editor warns if you add the same processor type twice.

    Both lists use [SerializeReference] so custom subclasses you write in your own assembly appear in the dropdowns automatically - no editor code required.

    Building at runtime¶

    [SerializeField] private BoolActionDefinition _interactDefinition;
[SerializeField] private Vector2ActionDefinition _moveDefinition;

private InputAction<bool>    _interact;
private InputAction<Vector2> _move;

private void OnEnable()
{
    _interact = _interactDefinition.Build();
    _move     = _moveDefinition.Build();

    _interact.Performed += OnInteract;
    _move.Performed     += OnMove;
}

private void OnDisable()
{
    _interact.Performed -= OnInteract;
    _move.Performed     -= OnMove;

    _interact.Dispose();
    _move.Dispose();
}

    Each .Build() call registers a new binding under a freshly generated GUID, so the same asset can be built multiple times (e.g. one per player) without collisions. The returned InputAction<T> is the same type you'd get from UPSInput.BindAs<T>(...).Complete() - .Read(), .Performed, and .TryGetGlyph() all work identically.

    Tip

    Definitions and custom action sets are not mutually exclusive - a custom InputActionsSet<T> can serialise [SerializeField] InputActionDefinition<T> fields and call .Build() on them inside Initialize(...), which gives you a set that's partly code-defined and partly asset-defined.

    Static API (UPSInput)¶

    Use the static API when an action does not belong to a long-lived set - for example one-off bindings, editor tools, or runtime-defined inputs.

    // Bind
UPSInput.BindAsBool("Interact")
        .ToButton(GamepadButton.ButtonSouth, ButtonTrigger.Press)
        .Complete();

// Subscribe / unsubscribe
UPSInput.Subscribe<bool>("Interact", OnInteract);
UPSInput.Unsubscribe<bool>("Interact", OnInteract);

// Toggle an individual action
UPSInput.SetActionState("Interact", active: false);

// Remove a binding entirely
UPSInput.Unbind("Interact");

    Device queries¶

    GamepadType pad         = UPSInput.GetGamepadType();          // None / Nintendo / PlayStation / Xbox
DeviceType[] connected  = UPSInput.GetConnectedDevices();     // Keyboard, Gamepad

    Vibration¶

    UPSInput.SetGamepadVibration(lowFrequency: 0.4f, highFrequency: 0.7f);
UPSInput.StopGamepadVibration();

    Device hot-plug events¶

    UPSInput.OnDeviceAdded   += device => Debug.Log($"Connected: {device}");
UPSInput.OnDeviceRemoved += device => Debug.Log($"Disconnected: {device}");

    Binding builder¶

    Danger

    This API is gamepad-only today. Mouse and keyboard support is on the Roadmap, and the binding entry points (To…, With…) will likely gain new overloads or be renamed when those sources land.

    Every binding follows the same shape - three required calls, with optional processors in between:

    BindAs...(name)  →  To...(…)  →  WithProcessor(processor)  →  Complete()

    Bool¶

    Source Method
    A physical button .ToButton(GamepadButton, ButtonTrigger)
    A semantic action .ToAction(GamepadAction, ButtonTrigger)
    Inversion .WithInvert() 
    UPSInput.BindAsBool("Jump")
        .ToButton(GamepadButton.ButtonSouth, ButtonTrigger.Press)
        .Complete();

    Float¶

    Source Method
    Left stick X / Y .ToXLeftStick() / .ToYLeftStick()
    Right stick X / Y .ToXRightStick() / .ToYRightStick()
    Triggers .ToLeftTrigger() / .ToRightTrigger()
    Inversion .WithInvert() 
    UPSInput.BindAsFloat("Aim").ToRightTrigger().Complete();

    Vector2¶

    Source Method
    Sticks .ToLeftStick() / .ToRightStick()
    D-pad .ToDpad()
    Deadzone .WithDeadzone(float)
    Axis inversion .WithInvertX() / .WithInvertY() 
    UPSInput.BindAsVector2("Move")
        .ToLeftStick()
        .WithDeadzone(0.15f)
        .WithInvertY()
        .Complete();

    Processors¶

    Processors transform input values between the source and the consumer. They implement IProcessor<T> and are attached with .WithProcessor(...).

    Built-in processors¶

    Processor T Behaviour
    InvertBoolProcessor bool Returns !value
    InvertFloatProcessor float Returns -value
    InvertXVector2Processor Vector2 Negates X, preserves Y
    InvertYVector2Processor Vector2 Preserves X, negates Y
    DeadzoneVector2Processor Vector2 Returns Vector2.zero if magnitude is below the deadzone threshold
    DelayVector2Processor Vector2 Normalises to cardinal axes and repeats with initialDelay / repeatDelay - designed for D-pad/Stick

    Custom processors¶

    Any class implementing IProcessor<T> can be plugged in:

    [Serializable]
public sealed class ScaleVector2Processor : IProcessor<Vector2>
{
    [SerializeField] private float _factor;

    public ScaleVector2Processor(float factor) => _factor = factor;

    public Vector2 Process(Vector2 value) => value * _factor;

    public IProcessor<Vector2> Clone() => (IProcessor<Vector2>)MemberwiseClone();
}

    Clone() is called when the same processor instance is shared across multiple bindings and one of them needs an isolated copy of the internal state - implement it via MemberwiseClone() unless you hold reference-type state.

    Usage:

    builder.BindAsVector2("Move")
       .ToLeftStick()
       .WithProcessor(new ScaleVector2Processor(1.5f))
       .Complete();

    Processors can be chained - each is applied in registration order.

    Glyphs¶

    TryGetGlyph() returns the controller-specific sprite for an action, so you can show the right icon in tooltips and prompts.

    Sprite icon = BaseInputActionSet.Instance.Apply.Press.TryGetGlyph();
// or via the static API
Sprite east = UPSInput.TryGetGlyph(GamepadGlyph.East);

    Authoring icon sets¶

    You need one GamepadIconsSet per platform you ship on.

    1. Create the icon sets

    Project window → right-click → Create → Upscale SDK → Gamepad Icons Set

    Name them descriptively, e.g. PlayStation5_Icons, Xbox_Icons, Switch_Icons.

    2. Assign sprites

    Open each set in the Inspector and drop a sprite into every GamepadGlyph slot (face buttons, D-pad, sticks, shoulders, triggers, Start / Select).

    3. Wire the sets into UpscaleSDKConfig

    Open your UpscaleSDKConfig asset and assign each platform's GamepadIconsSet to the matching field. GlyphProvider will pick the correct set at runtime based on UPSInput.GetGamepadType().

    Tip

    The optional UpscaleSDK-Extras.unitypackage already includes pre-configured GamepadIconsSet assets for PlayStation / Xbox / Switch.
